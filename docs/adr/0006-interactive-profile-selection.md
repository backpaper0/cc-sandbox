# `--profile`に値を省略すると、既存プロファイルから対話的に選択できるようにする

`--profile <name>`は名前を正確に覚えて手打ちする必要があり、クライアントや案件ごとにプロファイルを増やす運用（[ADR-0003](0003-auth-injection-per-host-profile.md)）と組み合わせると、どんな名前を作ったか忘れて`~/.cc-sandbox`を覗きに行く手間が生じていた。`--profile`に値を渡さなかった場合（`--profile`が末尾に来る、次のトークンが他のフラグに見える、または`--profile=`のように`=`の後が空）を「一覧から選ばせてほしい」という意思表示として扱い、`~/.cc-sandbox/env.*`のうち`resolve_profile_env_file`と同じ文字種チェックを通った名前をアルファベット順にbash組み込みの`select`で提示する方式にした。候補が0件、非TTY環境、キャンセル（空入力/Ctrl-D）はいずれも既存の`resolve_profile_env_file`と同じ「黙って続けず失敗する」方針でエラー終了する。選択結果は`Using profile: <name>`と表示してから、明示的に`--profile <name>`を渡した場合と全く同じ経路（`resolve_profile_env_file`）に流す。

## Considered Options

- 別フラグ（例: `--pick-profile` / `-i`）を新設する方式 — `--profile <name>`とは別の覚えることが増える上、「一覧を見て選ぶ」のは`--profile`の意味の自然な延長でしかないため見送った
- `up`から独立した専用サブコマンド（例: `bin/cc-sandbox profiles`）で選んだ名前を確認し、改めて`--profile <name>`に渡す2段階方式 — スクリプト向けの一覧出力には向くが、今回欲しいのは対話選択そのものであり、2段階に分ける利点が無いため見送った
- プロファイルの一覧のみを出力する非対話コマンドを別途用意する案 — 今回の要望は「選択できること」であり、一覧出力だけの需要が出た時点で別途追加すればよいため見送った
